# Preserve Case Header Formatter

A `StatefulHeaderKeyFormatter` consumed by the HTTP/1 codec (both server
and client). Envoy's HeaderMap stores keys lowercased; to forward HTTP/1
messages with their original casing intact, the codec calls into a
stateful formatter to remember the original case of each parsed header key
and reproduce it on serialization. This extension records the first-seen
casing of each header and - optionally - re-cases Envoy-generated headers
into proper-case.

Proto: `envoy.extensions.http.header_formatters.preserve_case.v3.PreserveCaseFormatterConfig`.

## Files
- `preserve_case_formatter.h/cc` - formatter implementation.
- `config.h/cc` - factory registration.

## Interface
- Implements `Envoy::Http::StatefulHeaderKeyFormatter`. The HTTP/1 codec
  calls `processKey(original_key)` while parsing and `format(lc_key)` while
  serializing; it also calls `setReasonPhrase` / `getReasonPhrase` if the
  response reason phrase should be preserved.
- Factory implements `Envoy::Http::StatefulHeaderKeyFormatterFactoryConfig`
  and is registered so HTTP/1 protocol options can select it by type URL.

## Logic
- `processKey` inserts the parsed key into a case-insensitive
  `StringUtil::CaseUnorderedSet`, which dedupes on lowercase but keeps the
  original casing as the stored string. Only the first casing wins
  (`preserve_case_formatter.cc:43`), which matches the observed/expected
  HTTP/1 behavior.
- `format(lc_key)` looks up the key in the remembered set:
  - If present, returns the original casing.
  - If not (the header was generated by Envoy rather than parsed), falls
    back to the configured `formatter_type_on_envoy_headers_`: either
    leave it lowercase (`DEFAULT`) or apply `ProperCaseHeaderKeyFormatter`
    (i.e. `Content-Length` instead of `content-length`).
- `setReasonPhrase` stores the upstream reason phrase if
  `forward_reason_phrase` is true; the codec pulls it back via
  `getReasonPhrase` when framing the response line.

## Key decision points
- `preserve_case_formatter.cc:15` - ctor switches on the proto enum
  (`DEFAULT` vs `PROPER_CASE`) to pre-build the fallback formatter.
- `preserve_case_formatter.cc:34` - `format` prefers the remembered key,
  then the fallback formatter, then the raw lowercase string.
- `preserve_case_formatter.cc:43` - only first-seen casing is kept.
- `preserve_case_formatter.cc:51` - reason phrase preservation is gated on
  `forward_reason_phrase`.

## Configuration
- `forward_reason_phrase` - copy the upstream HTTP/1 reason phrase to the
  downstream response.
- `formatter_type_on_envoy_headers` (`DEFAULT` or `PROPER_CASE`) - casing
  to apply to headers Envoy generates itself (since they have no parsed
  original).
